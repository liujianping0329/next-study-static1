AI基础 #76｜AI + 零售

原资料：《AI大模型面试题-基础篇》。下述工程化说明属于 AI补充/纠错，用于转换到 Java / Spring Boot / Spring AI 面试语境。

白话理解

智能导购、库存预测和用户画像分别涉及生成、预测和数据治理，不能用一个 LLM 替代所有专用模型。

机制 / 控制流

输入 → 识别目标与约束 → 核心处理/模型或工具 → 校验 → 输出
                     ↘ 超时 / 权限 / 数据 / 质量问题 → 重试、降级、人工或失败

Java / Spring 项目怎么落地

把确定性控制放在 Java 宿主：Service 保存状态，DTO/Schema 约束输入输出，Tool 层做权限和参数校验，数据库/Redis 保存必要状态；Spring AI 负责模型调用、Tool Calling、RAG 等适合模型参与的环节。所有关键路径增加 timeout、日志、Metrics 和可回归评测。

为什么这样设计 / 常见坑

模型输出具有概率性，因此不能把 Prompt 当事务、权限或安全边界。任何会改变真实数据的动作都要有幂等、鉴权和失败恢复；任何资料中的固定版本、比例和框架结论都应视具体版本验证。

面试追问

  1. 如果模型结果错了，哪一层负责兜底？——确定性业务层/验证层。
  2. 怎么证明优化有效？——固定评测集 + 线上指标比较质量、P95、成本。
  3. 什么时候不该用 LLM？——规则明确、低延迟、强确定性任务优先普通代码。

30 秒口述

智能导购、库存预测和用户画像分别涉及生成、预测和数据治理，不能用一个 LLM 替代所有专用模型。 我会把模型能力放进受控的 Java 工作流，用权限、校验、可观测性和评测保证它能稳定上线，而不是只看 Demo 是否能回答。

一句话：模型负责智能，系统负责边界和正确性。
