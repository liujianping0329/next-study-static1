1. 为什么 2026 年不能再把 Pulsar 固定背成 Broker + BookKeeper + ZooKeeper？

答完后展开

2. Tenant 与 Namespace 分别是什么边界？逻辑隔离为什么不等于物理隔离？

答完后展开

Tenant 是高层多租户边界，Namespace 是更细的业务/策略边界；底层资源仍可能共享。

答完后展开

Scope 不保证线程安全；普通 prototype 注入 singleton 通常只在 singleton 创建时解析一次。

② 新题 1｜Spring 事务传播属性与隔离级别

《后端高频面试题大集合》Spring #2｜正式后端 #77

概念→原理

传播属性回答“调用链已有事务时当前方法怎么办”；隔离级别回答“并发事务之间能看到多少彼此的数据”。

传播：REQUIRED / REQUIRES_NEW / SUPPORTS / NOT_SUPPORTED / MANDATORY / NEVER / NESTED
隔离：DEFAULT / READ_UNCOMMITTED / READ_COMMITTED / REPEATABLE_READ / SERIALIZABLE

为什么→项目怎么用

订单与库存需要同成败通常用 REQUIRED；确实需要独立提交才考虑 REQUIRES_NEW。隔离级别在一致性、锁竞争与吞吐间权衡。

AI补充/纠错：当前 Spring @Transactional 默认 REQUIRED + DEFAULT；DEFAULT 沿用底层事务系统/数据库默认隔离级别。REQUIRES_NEW 使用独立物理事务并额外占用连接，滥用可能耗尽连接池。

常见坑→面试怎么说→追问

不要把传播与隔离混为一谈，也不要把 NESTED 当独立物理事务。面试可说：传播解决调用关系，隔离解决并发可见性；Spring 默认 REQUIRED + DEFAULT。

② 新题 2｜@Transactional 为什么会失效？

《后端高频面试题大集合》Spring 事务相关题｜正式后端 #78

概念→原理

声明式事务通常依赖 Spring AOP Proxy 拦截方法调用，再由事务拦截器开启、提交或回滚事务。

Controller → Spring Proxy → Service → DB

为什么→项目怎么用

调用没有经过代理时增强可能不执行，典型是同类 self-invocation。事务边界优先放在 Service 业务用例层。

AI补充/纠错：现代 Spring 对方法可见性支持比旧资料更宽，但 Proxy 模式核心限制仍是外部调用经过代理。默认 RuntimeException/Error 回滚，checked Exception 默认不回滚，可用 rollbackFor 调整。

常见坑→面试怎么说→追问

self-invocation、异常被 catch 后吞掉、checked Exception 回滚预期错误、异步线程误以为继承事务。面试先说“代理边界 + rollback 规则”。

② 新题 3｜REQUIRED、REQUIRES_NEW 与 NESTED

《后端高频面试题大集合》Spring 事务传播相关内容｜正式后端 #79
REQUIRED      → 加入外层事务
REQUIRES_NEW  → 挂起外层，创建独立物理事务
NESTED        → 常在同一物理事务内使用 Savepoint

为什么→项目怎么用

强一致链路优先 REQUIRED；必须独立提交的少数操作才考虑 REQUIRES_NEW；NESTED 适合事务管理器支持 Savepoint 且业务允许局部回滚的场景。

AI补充/纠错：REQUIRES_NEW 不是“更安全的 REQUIRED”。外层连接保持绑定，内层还要申请连接，高并发可能导致连接池耗尽。NESTED 的支持范围取决于事务管理器。

面试怎么说→追问

一句话：REQUIRED 复用外层；REQUIRES_NEW 新开独立物理事务；NESTED 通常靠 Savepoint 做局部回滚。追问重点是连接池与 UnexpectedRollbackException。

② 新题 4｜Skills 怎么实现，怎么和 MCP 配合？

《AI应用开发面试题 / Agent / RAG》Tool Calling / MCP 1.1.6

概念→原理

原资料把 Skill 概括为结构化 Prompt 模板 + 关联工具集合 + 执行逻辑。

任务识别 → 按需激活 Skill
        → 注入 instructions/examples
        → 注册所需 Tool/MCP
        → Agent 执行

为什么→Spring 项目怎么用

Spring Boot 可把 Skill 元数据、指令模板、允许 Tool 列表做成配置，由路由层选择，再通过 Spring AI 注册当前任务需要的 Tool；外部系统能力由 MCP 提供。

AI补充/纠错：原资料的 Python class 只是实现示例，不是统一协议标准。Java/Spring AI 应把 Skill 理解为应用层编排模式；权限必须由 Java/Tool/MCP 服务端强制执行。

常见坑→面试怎么说→追问

不要把 Skill 当安全边界，也不要全量加载。面试可说：Skill 教 Agent 怎么做事，MCP 给 Agent 外部工具；二者按任务组合。

② 新题 5｜Fine-Tuning 与 RAG 怎么选？

《AI大模型面试题-基础篇》RAG #31

概念→原理

Fine-Tuning 主要改变模型行为/任务能力和输出偏好；RAG 在推理时补充外部知识和证据。

动态企业知识 / 可追溯 → RAG
稳定行为 / 风格 / 特定任务 → Fine-Tuning
实时精确数据 → Tool / API
复杂场景 → 组合使用

为什么→项目怎么用

频繁变化的政策、商品和文档不适合每次重新训练；固定输出风格、领域任务模式可能适合微调。

AI补充/纠错：Fine-Tuning 不是数据库，RAG 也不是“让模型学会新能力”。RAG 受检索质量限制；微调知识更新成本高；实时精确数据仍应走 API/Tool。

常见坑→面试怎么说→追问

不要为更新 FAQ 就微调，也不要用 RAG 做严格计算。面试：知识更新与引用优先 RAG；稳定行为可微调；实时数据用 Tool/API，生产系统常组合。
