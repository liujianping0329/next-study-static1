Agent原题补漏｜Workflow 和 Agent 有什么区别

来源：《AI应用开发面试题 / Agent / RAG》。题目来自原资料；下面的 Java/Spring 工程化说明属于 AI补充/纠错。

先讲清楚

Workflow 的路径主要由开发者预定义，Agent 则让模型在受约束的行动空间内动态决定下一步。面试重点是确定性、灵活性、成本和可控性的取舍。

机制 / 项目落地

Request / Task → 校验与路由 → 核心机制 → 外部依赖/Tool/DB
                              ↓
                    timeout / retry / fallback
                              ↓
                       metrics / trace / audit

AI补充：面试回答要说明“为什么需要 → 怎么工作 → 失败会怎样 → 项目如何落地”。Spring Boot / Spring AI 中把确定性约束放在 Java 服务层；模型、检索和 Tool 是能力组件，不是权限、事务或安全边界。

常见坑

不要只背框架 API；不要把重试当可靠性万能药；不要让 LLM 自己决定权限和最终一致性；涉及具体版本或默认值时以项目实际版本验证。

面试追问

  1. 不用这个机制会发生什么？
  2. 它和相邻方案最大的边界差异是什么？
  3. 线上失败时你先看什么指标、日志或 Trace？

30 秒口述

Workflow 的路径主要由开发者预定义，Agent 则让模型在受约束的行动空间内动态决定下一步。面试重点是确定性、灵活性、成本和可控性的取舍。 实际项目中我还会补上超时、权限、幂等、监控和回归测试，确保方案不只在 Demo 中可用。

一句话：先讲机制，再讲边界，最后落到生产控制。
